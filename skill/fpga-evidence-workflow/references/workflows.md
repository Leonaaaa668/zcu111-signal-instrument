# 六项工作流

需要案例来源时读casebook；执行命令默认从本技能根目录运行。下列步骤用于组织工作，不授权操作他人的板卡。

## A 信号链契约与数据预算

适用：高速ADC/算法拟交给ARM，或者“采样率、AXI时钟、每拍样本数、DMA字节率”混淆。

1. 画出实际链路：模拟输入→ADC→RFDC混频/抽取→自写PL处理→搬运对象→PS算法→显示。分别标记每级采样率和字节格式。
2. 每级抽取后的样本率为上一层除以抽取倍数。传输字节率按**容器位宽**计算，不按ADC有效位数猜测；16bit的I/Q各一路为每复样本4字节。
3. 明确DMA搬的是原始IQ、FFT复数、功率谱还是特征。算包头、每帧点数、显示帧率和突发长度；不能以平均刷新量证明FIFO/DDR突发带宽足够。
4. 区分信息保留目标：按帧快照可以用于当前频谱显示，不能因此宣称连续无丢点IQ录制、无缝瞬态捕获或全带实时监测。
5. 有预算差距时先决定搬运对象和PL/PS划分，再做实现。不要只凭“ARM更方便”把未预算的高速流整体搬到PS。

工具：rate-budget。参数decimation为逗号分隔的逐级倍数，component-bits必须是实际打包容器位宽；未对齐打包格式要另算填充。
本例2.4GS/s÷2÷8=150MS/s；原始IQ是600MB/s，而256字节头+65536×8字节功率谱是524544字节/包。10包/s只约5.25MB/s，二者不是同一工作负载。
失败边界：多通道、TLAST空隙、缓存一致性、DMA描述符、总线仲裁、DDR效率与UI开销仍需实测。工具只给算术预算。

## B 联调的最小可证伪实验

适用：MMIO读卡死、驱动probe迟滞、RCU stall、界面无输入、生成波形找不到。

输入最小集：硬件/软件身份、最后一个成功动作、第一处失败位置、原始日志、外设所有者、时钟/复位关系、当前采集/播放状态。

- 先检查文件和离线配置。恢复连接并不自动证明硬件身份、镜像或位流相同。
- 已知某次寄存器读取可能阻塞总线时，不以“只读”名义反复重试。保留访问地址和最后输出；下一次实验改变一个有证据的条件。
- 建立控制时钟、数据时钟、复位源/释放链、DDR校准与寄存器可达性关系。不要把任何RESET编号、GPIO或延时值从案例照抄到另一设计。
- 配置资源有单一所有者。新的自定义驱动不应与通用DMA/UIO/GPIO驱动同时访问同一寄存器。
- 将“取得时钟引用”“寄存器可读”“DMA传输”“回读正确”“RF指标”逐层验收。前层成功不替代后层。
- 真实操作只在任务已授权、运行状态及影响明确时执行；能在已授权范围完成的检查不额外反复询问。

输出：一个实验记录与明确停止点。例：先证明该复位线来自新工程启动代码，再在停采停播条件进行一次恢复；若仍在同一MMIO位置阻塞，保留证据并停止继续访问。
本项目“仅保留时钟”没有解决问题；正确复位链/DDR就绪后MMIO、48MB回读与停播通过。经验是核对依赖顺序，不是“任何DMA故障都脉冲EMIO95”。
GUI/存储分支见pitfalls。模型建议被观察否定时，记录失败假设，避免把第一次猜测写成最终根因。

## C 独立黄金参考

适用：DSP文件存在、长度正确，但相位、缩放、顺序或数值仍可能错误。

先冻结：I/Q打包顺序、有符号位宽、端序、采样率、抽取倍数、NCO符号约定、FFT自然/位反序、fftshift、窗、缩放、流水线延迟和TLAST含义。
建立参考时不复制受测实现的关键索引。例如发射RRC用独立接收端匹配滤波和已知符号集合检验；只对比同一卷积公式的两个副本可能共享错误。

1. 整数定点/功率/协议字段：先精确比对。uint64不能先转浮点，超过2^53可能掩盖1LSB差异。
2. 浮点模型与固定点FFT：预先说明误差来源和绝对/相对容限，不为让测试过而临时增大容限。
3. 对齐延迟和bin映射后才比较，不用寻找任意移位、共轭、增益把错误“拟合掉”；若需要估计，明确输出估计参数及适用目的。
4. 除正例外，验证掉样、重复索引、TLAST/包长异常、旧票据、溢出和反压稳定性。错误帧应明确标记/拒绝，不能伪装成可信结果。
5. 实测RF质量需要外部IQ/仪器与恢复链路；数字文件误差不是RF EVM，更不是BER。

工具输入CSV为index,value，索引0起连续唯一；mode=exact要求整数，mode=tolerance用atol+rtol×abs(reference)。这些容限不具有自动物理单位意义。
示例CSV来自真实RTL快照仿真中第一包的128个功率载荷；参考按测试平台已知刺激公式推导。故障文件是另造的1bit修改，非原始测量。
失败边界：工具不会替你证明缩放、时序、模拟通道或FFT算法正确；先补契约，不能把CSV逐值一致泛化成整机正确。

## D 有边界的功率标定

适用：从Digital peak改为dBm/dBW，或给不同调制复用CW补偿。

- 先定义参考面：端口还是同一线缆末端；频率、波形、线缆/衰减器、参考仪器设置、平均方法、检波/积分带宽均入台账。
- 数字幅度缩放为10^(ΔdB/20)，功率为10^(ΔdB/10)。dBW=dBm−30；转换单位不扩展标定范围。
- 用复RMS sqrt(mean(I²+Q²))说明功率关系；CW、QAM、PSK在相同分量峰值下RMS不同，QAM峰均比还限制允许平均功率。
- 脉冲区分脉内与周期平均。理想平顶占空比D的差为10log10(D)，实际软边沿需按样本能量与窗口定义核对。
- QAM单个频谱峰值、最大保持不等于带内总平均功率；需满足带宽/检波要求的通道积分或合适的功率测量。
- 补偿估计使用的点与预留检查点分开；同一条件重复读数用于重复性检查。不要在看到预留点后再把它纳入拟合并继续叫独立验收。

power-check要求context/request的频率、波形、参考面、setup_id相同，目标在范围内，读数为一个holdout点且至少三次。fit_point_ids是声明，脚本不能证明历史上真的没有偷用该点；需配原始台账。
本项目-25dBm点与原参考读数均值约差-0.0067dB，仅表明这个点的一致性。参考仪器不确定度未知，不能据此宣布整机绝对精度0.01dB或全范围0.1dB。
失败边界：换频、换线、换调制、过载、削峰或接收平均配置改变时，旧补偿不可自动应用；程序应拒绝/显示未标定。

## E 先证明可比再计算优化率

对比前核对器件/速度等级、工具版本、综合或布线阶段、时钟目标、采样率、FFT最大点数、位宽、通道、功能集合、缓存与调试核、约束。
同一FPGA不意味着同一功能；把DMA、缓存、Zoom或调试核增减造成的差异算成纯实现优化会误导。

compare-reports从完整报告提取LUT、寄存器、BRAM、DSP，缺行不当0。contexts中的条件必须来自实际源文件/BD/配置；未知值null会阻止严格等功能比较。
脚本只检查你提供的元数据一致性，不能证明元数据是真实；附其来源。原生setup/hold/pulse表单独报告，资源比较通过也不代表时序通过。
本例旧版92932 LUT、555 DSP，当前72273 LUT、183 DSP；旧Zoom0..6被裁到0且流水线/复位改变，故输出NOT_COMPARABLE，不计算“等功能节省百分比”。旧WNS-0.109ns，不能作为已达目标频率的实测基线。
如果必须严格等功能，另建立配置一致的旧实现基线并保存来源/报告；否则标题改为面向目标工况的裁剪与实现迭代，明确范围变化。

## F 冻结与交付

把“当前源码、构建输入、生成产物、部署运行、人工确认、冷启动”分成不同状态，记录每层哈希或回执。
维护一张用户状态表：板卡/接线/源开关、版本、最后确认时间、下一次需要改变的条件；不要把旧版人工确认继承给新版。

1. 原冻结包只读保留。新版本独立命名，避免覆盖旧BIT/驱动/GUI或混用旧缓存。
2. 发布输入包含RTL、BD Tcl、约束、系数、配置、依赖版本、构建/运行入口、少量参考数据；排除可再生成缓存和敏感信息。
3. 在新目录验证恢复，记录是否仅恢复工程、是否重编译应用、是否重做完整综合实现/镜像。没有做的层级明确写未做。
4. 对运行包与启动镜像分别算哈希，启动入口匹配该次包。新编译产物不能沿用原包硬编码哈希。
5. manifest验证拒绝缺失/改动、重复路径和越界；它不检查行为正确。记录验证日志、适用内核/硬件接口和回退方法。
6. 上板显示、输入、单次采集、连续接收、上传回读、播放停止、断电冷启分别验收。默认停播只是软件保护，不等于测得RF端口没有任何杂散。

使用release_receipt模板保留tests_passed和tests_not_run，不能用一句“全流程通过”覆盖边界。
本项目V15有人工冷启动确认，V16只做在线替换/测试/人工交互确认；V16不得借用V15冷启动结论。
